# Design

## Context

The window picks its colors in one place: the view reads `cx.system_dark()` every frame, keeps it in `Desk::dark` for rows built later as the list scrolls, and passes `pal::pal(dark)` down; `pal.rs` holds one light and one dark set of about 40 colors. The lanes and the inspector are wrapped in `rune::memo`, and their versions include `dark`, so a change of appearance redraws them; a change of theme must join those versions.

Rex Beta 0.1.0 (build 1829) keeps its themes in `Rex Beta.app/Contents/Resources/SuperUI_SuperDesignTokens.bundle/Contents/Resources/themes.json` (2.5 MB): a list of 41 themes, each with `id`, `name`, `appearance` (`light` or `dark`), `source` (the colors its editor shows as hex: background, foreground, cursor, selection, 16 ANSI colors), a 256-color `palette`, and `semantic`, 73 roles as Display P3 components (`canvas`, `surface`, `surfaceSubtle`, `surfaceRaised`, `stroke`, `strokeSubtle`, `content`, `contentSecondary`, `contentTertiary`, `controlHover`, `accent`, `accentOnSolid`, `accentDim`, `danger`, `dangerContainer`, `success`, `warning`, `info`, `terminalBackground`, `terminalAnsi0`…`terminalAnsi15`, and more). Rex draws the semantic roles, and they are more saturated than the source hex: Merino Light's cursor is `#0969da` in the source and P3 (0.042, 0.375, 0.928) as its accent, `#0061f6` in sRGB. Rex stores its choice as `Workspace.interfaceStyle`, `Workspace.lightThemeID` and `Workspace.darkThemeID`.

Rune at rev `781e2b6d` gives what the panel needs: `rune::MenuItem` with a key equivalent in the app menu (`App::menu_item`); `rune::prefs::Prefs` (JSON in `~/Library/Application Support/<app id>/prefs.json`, written whole through a rename, a broken file moved aside; `Prefs::memory()` keeps nothing). Its `El::modal(click_outside, dismiss)` takes Tab itself while nothing inside is focusable, as here, so the panel does without it. It has no call to set a window's `NSAppearance`, and it draws in sRGB.

This change reads no log fields and does not touch parsing; the parse time of the log corpus does not change.

## Goals / Non-Goals

**Goals:**
- The window looks like Rex in the same theme.
- One file of themes in the repository, regenerated by a script, so a new Rex build is one command away.
- Frames without a window stay reproducible: they never depend on a file on the author's Mac.

**Non-Goals:**
- A theme editor, user themes, Display P3 drawing.
- A separate Settings window: a second window needs its own state and menu handling in Rune; a panel over the window is enough.

## Decisions

### The themes file

`crates/tokprof-desk/themes/themes.json`, built in with `include_str!` and parsed once:

```json
{ "source": "Rex Beta 0.1.0 (1829), themes.json",
  "themes": [ { "id": "merino-light", "name": "Merino Light", "appearance": "light",
                "colors": { "canvas": "#f6f7f9", "accent": "#0061f6", "accentDim": "#0061f61c", … } } ] }
```

`colors` holds only the roles the window uses (the list in Context), each as sRGB hex with an alpha byte when it is not opaque. `themes/import.py <themes.json>` writes it: it converts each semantic role from Display P3 to sRGB (linear P3 → XYZ → linear sRGB, clipped to 0–1), keeps the themes in Rex's order, and fails when a role is missing. The file is about 50 KB.

*Alternatives.* (a) The source hex instead of the semantic roles: they are what Rex's editor prints, but not what it draws; the window would look duller than Rex and would have to invent surfaces and lines. (b) Reading Rex's file at run time: no copy in the repository, but no themes without Rex; the author chose a file of tokprof's own.

### From a theme to the window's colors

`pal::pal(theme)` replaces `pal::pal(dark)`; the fields of `Pal` stay, so no drawing code changes:

| Window | Theme role |
| --- | --- |
| bg, bar, track, panel | canvas, surfaceSubtle, terminalBackground, surfaceRaised |
| row_line, hour, line | strokeSubtle, strokeSubtle, stroke |
| ink, ink2, ink3, neutral | content, contentSecondary, contentTertiary, contentTertiary |
| hover, accent, on_accent, sel | controlHover, accent, accentOnSolid, accentDim |
| now, cold, cold_dot, stop, cold_bg | danger ×4, dangerContainer |
| warm, warm_dot, work, tail | success ×3, success at 30% (25% light) |
| wait, write | warning at 45% (30% light), warning |
| read, bars, you | info, info, info at 35% (22% light) |
| out, message | terminalAnsi6 |
| question | terminalAnsi5 |
| agents | terminalAnsi5, terminalAnsi4, terminalAnsi6, terminalAnsi3 |

The alphas are those the built-in pair used, so a mark sits on its background as before.

### The settings and where they live

`Appearance { System, Light, Dark }` and two theme ids, stored as `appearance`, `light_theme` and `dark_theme` in `Prefs::open("io.github.ignatov.tokprof")`, the bundle identifier of `tokprof.app`, so the bundle and the bare binary share one file. `dark = match appearance { System => cx.system_dark(), Light => false, Dark => true }`, then the theme is the light or the dark one. The theme id joins the memo versions of the lanes and the inspector. A pick writes only a value that changed; a write error sets the bar's status. A headless start uses `Prefs::memory()`; `--colors` sets both theme ids to the one given, and its appearance sets `Appearance`.

### The panel

`Settings…` with ⌘, in the app menu; `on_key` takes ⌘, too, for a headless script or a menu that failed. The panel is a `settings: Option<SettingsPanel>` in `Desk` holding which of the three parts has the keyboard; while it is set, `on_key` sends every key to it, except ⌘Q.

The panel follows the look of Rex's own settings, which the author likes: large rounded corners, parts as soft groups instead of boxes with borders, pills for buttons and keys, and pictures of the themes rather than strips of swatches.

A card 760 points wide, at most the window's height less 80, radius 22, in the middle, over a scrim of the background at 35% that blurs the window (backdrop blur, σ 10) and covers it: a click on the scrim closes the panel, and the card keeps its own clicks, so nothing behind it is pressed. Its head holds `Settings` and a pill with the theme the window shows; its foot the keys as keycaps (`Tab` section, `← → ↑ ↓` choose, `⏎` done) and `Done`, a pill in the accent. Between them the body scrolls, with three parts, each a title over a group of radius 16 in the bar's color, ringed in the accent (outline 2, offset 2) while it has the keyboard:
- `Appearance`: three tiles, each a 74-point picture of a window (its bar, two lines of text, an accent and a green) in the chosen light theme, the chosen dark theme, or both side by side for `As in system`, the label under it; the chosen tile ringed and its label in the accent.
- `Light theme` and `Dark theme`: grids of 4 columns of cards, each a 78-point picture of the theme's canvas with a `~/` prompt pill in its raised surface and text, `tokprof` in its secondary text, and five overlapping dots (accent, success, warning, danger, info), the name under it; the chosen card ringed and its name in the accent.

In a grid ← → go to the card before and after, ↑ ↓ four cards back or on (staying put where there is none), Home and End to the ends; every move picks the theme, so the window shows it at once, and scrolls the card into view. Tab scrolls the part it reaches into view. A pick saves at once; there is no Cancel, as in macOS settings.

## Risks / Trade-offs

- [The themes are Rex's work, published in an MIT repository] → The author decided to carry them. The file and the README name Rex Beta and its build as the source, and the script keeps them apart from tokprof's own code.
- [A new Rex build renames or drops a theme] → A saved id that the file no longer has gives the default theme; the script fails loudly on a changed format instead of writing a partial file.
- [Colors outside sRGB clip] → A few saturated P3 roles land on the sRGB edge; Rex on an sRGB display shows the same.
- [The title bar buttons keep the system's look under a forced appearance] → They are small and look nearly the same in both; a later Rune with a window appearance call can fix it.
- [⌘, reaches the menu item before `on_key`] → Both call the same toggle, so the panel opens or closes once.
