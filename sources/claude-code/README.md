# tokprof-source-claude-code

tokprof's source of Claude Code transcripts.

- **Where:** `$CLAUDE_CONFIG_DIR/projects/<project>/<session>.jsonl`, by default under `~/.claude`. A session's subagents are in `<session>/subagents/agent-<id>.jsonl`, with what started each in `agent-<id>.meta.json` (`agentType`, `description`, `toolUseId`).
- **Requests:** `assistant` lines with `message.usage` (`input_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, `cache_creation.ephemeral_5m_input_tokens` and `ephemeral_1h_input_tokens`, `output_tokens`, `iterations` for advisor calls). Since 2.1.300 the prompts come from the request-audit lines `api-request`, `api-request-shape` and `api-request-blob`. Blobs of role `system` are Claude Code's reminders (environment, hook context, file-change notes), not prompts; seen in 2.1.300–2.1.312. One such blob joins the reminders of a turn, so it is split at each blank line before an opening that the session-logs spec lists, such as `[SYSTEM NOTIFICATION` or `The following skills are available`; seen in 2.1.300–2.1.316.
- **Compaction call:** not logged. Claude Code runs it as a fork of the conversation that shares its cache, so tokprof prices a compaction on a warm cache as a read of the context.
- **Session facts:** `sessionId` and `cwd` from the first lines, `compact_boundary` with `compactMetadata.trigger`, the idle-compaction notices (`system` lines with subtype `informational` whose `content` starts with `Compacted while idle`, seen in 2.1.302–2.1.310, or `Compacted using a summary written while you were away`, found in the 2.1.316 binary and not yet seen in a log), `cost-state` (`totalCostUSD`, `startTime`, both seen in 2.1.284–2.1.312: a resumed process restores the counter with its `startTime`, and a process that found no `cost-state` counts from zero under a new one, so the counter is the sum of the highest `totalCostUSD` per `startTime`), `ai-title` and `custom-title`.
- **Last activity:** the top-level `timestamp` of the last line that has one. `cost-state`, `last-prompt`, `ai-title`, `custom-title`, `mode`, `permission-mode`, `tools-used`, `atis-latch`, `file-history-snapshot`, `api-request-blob`, `relocated`, `worktree-state` and `agent-name` lines carry none. Claude Code also writes them when the IDE resumes a session that then does nothing, so they do not count. Seen in 2.1.284–2.1.316.
- **Triggers:** the `tool_use` items of each response, grouped by `message.id` (the tool `name`, and `input.command` for `Bash`), and the user lines after them: typed prompts and slash commands, `<task-notification>` and `[Request interrupted`. Seen in 2.1.284–2.1.312.
- **Hand-offs:** only in the main conversation: not in a subagent's transcript, and only lines without `isSidechain` or an `agentId`. An `assistant` line whose `message.stop_reason` is set and is not `tool_use` ends the turn, and so does a `<synthetic>` message such as an API error. The lines of one `message.id` end it once, at the latest `timestamp`. A `user` line whose text starts with `[Request interrupted` is an interrupt; one that starts with `<task-notification>` or `<cross-session-message` is a wake. `isMeta` user lines are neither. An `attachment` line whose `attachment.type` is `queued_command` is a message the user typed while the agent worked when its `attachment.origin.kind` is `human`; `peer` and `task-notification` are other sessions and background tasks. A log without `origin` counts a `prompt` that is not `isMeta` and does not start with `<`. Such a `prompt` can also be a list of content blocks, read by its first text (seen in 2.1.286–2.1.312). A `tool_use` of `AskUserQuestion` or `ExitPlanMode` is a question, and the `tool_result` with its id is the answer. Seen in 2.1.310–2.1.316.
- **Request times:** a request was sent at the `timestamp` of its `api-request` line (2.1.300–2.1.316), or, without audit lines, at the latest `user` line of its chain before its response (2.1.284–2.1.299; `attachment` lines do not count, since Claude Code stamps some of them with the response). It ended at the latest `timestamp` among the assistant lines of its `message.id`, never before its send.
- **Retries:** a `system` line of `subtype` `api_error` (`retryAttempt`, `retryInMs`, `error.formatted`) follows an attempt that failed; the next `api-request` of the same `agentId` repeats it, and the answered attempt counts the failed ones from the first. Without audit lines, the errors between a request's input and its response are its retries, and the answered attempt went at the last error's `timestamp` plus its `retryInMs`. Seen in 2.1.287–2.1.316.
- **Call outcomes:** a `tool_result` with `is_error` failed (2.1.287–2.1.316). It was refused when its text starts with `The user doesn't want to proceed with this tool use`, `User rejected`, `[Request interrupted by user for tool use]` or `MCP tool call has been cancelled likely by a user interaction`. It was denied when its `user` line has `permissionDecision.decision` `reject` (2.1.300–2.1.316), or its text starts with `Permission to use ` and holds ` has been denied`, or starts with `Permission for this command was denied by a built-in`. A failure keeps its first line, or for `Exit code <n>` the code and the last line of the output, without `<tool_use_error>` tags. A search that found nothing has `toolUseResult.returnCodeInterpretation` `No matches found` and no `is_error`, so it worked.
- **Version-control actions:** the `input.command` of a `Bash` `tool_use`, in every part of the command, for `git commit`, `git push` and `gh pr create`; the outcome comes from its `tool_result` as for every call. Seen in 2.1.284–2.1.317.
- **What a wake reports:** the `<summary>` of a `<task-notification>`: `Agent "…"` is a subagent; `Background command "…"` and `Monitor …` are a background command; anything else, such as a goal check-in or a notice written on resume, and a `<cross-session-message`, is something else. Seen in 2.1.291–2.1.316.
- **Sessions a program ran:** the first `entrypoint` of the transcript is `sdk-cli`, as `claude -p` writes it. `sdk-ts` and `cli` are sessions someone typed in. Seen in 2.1.310–2.1.316.
- **Handoff note:** user prompts, the `TodoWrite` list, `Edit`, `Write`, `MultiEdit` and `NotebookEdit` file paths, `Read`, and `Bash` commands.
- **API:** every request goes to the Anthropic API.
- **Setup hints:** they name `skillListingBudgetFraction` (default 0.01 of the context window) and `skillOverrides` for skill listings, both in the settings schema of 2.1.316; `CLAUDE.md`, `AGENTS.md` and the auto-memory `MEMORY.md` for instructions; `/mcp` for deferred tool lists.
- **Names a share file keeps** (`PUBLIC_NAMES` in `src/lib.rs`): the names that ship with Claude Code, read from the bundled code of the 2.1.316 binary, plus the two tools 2.1.317 adds (`ReadWidgetContext`, `WrapUp`).
  - Tools: every built-in tool definition; the server tools sent to the API (`advisor`, `web_search`) and the deferred-tool stub `DeferredToolPlaceholder`; the aliases it accepts (`Task`, `KillShell`, `KillBash` and others); and the retired tools it still recognizes (`BashOutput`, `TaskOutput`, `MultiEdit`, `LS`, `NotebookRead` and others), which transcripts of 2.1.284 and later can carry.
  - Slash commands: the built-in commands and their aliases, and the bundled skills, which can be typed as commands.
  - Skills: the bundled skills (registered with source `bundled`), the skills of the built-in plugins, the prompt commands the Skill tool can call (`init`, `security-review`, `commit-push-pr`), the bundled workflow `deep-research`, and the skill aliases such as `review`.
  - Subagent types: the built-in ones (`baseDir: "built-in"`), such as `general-purpose`, `Explore`, `Plan` and `fork`, and those of the built-in `claude-test` plugin.
  - MCP tools are named `mcp__<server>__<tool>`; a plugin's server is `plugin_<plugin>_<server>`.
  - Left off: the built-in MCP servers (`ide`, `claude-in-chrome` and others), since a user can name a server the same way; `SlashCommand` and `output-style-setup`, which 2.1.316 no longer has.

The fields and versions are the ones the session-logs spec names; `tests/fixtures` holds a synthetic transcript with a subagent, a compaction, one hand-off of each kind, a failed, a refused and a denied call, and a request retried after an API error.
